# 012 — 发布复现与赛事证据

> Git evidence: `3c85f16`.

## 目标提示

把已完成的教学实验台变成评委可在十分钟内复现、可用真实浏览器验证、能清楚区分原创代码与第三方事实/依赖的参赛交付物。

## 验收设计

- 手动 FK：改变关节 1 后，角度显示和末端遥测同步更新。
- IK/轨迹：默认可达目标成功求解，轨迹先预览后播放并完成。
- Agent 安全：覆盖工作区的挑战障碍物必须阻断轨迹，关节最终值不变。
- 五秒帧率：在真实 Chrome 里统计 `requestAnimationFrame`，门槛为平均 30 FPS。

## AI 调试链

首次浏览器测试有两类环境/测试问题：Playwright 浏览器下载在 197.5 MiB 的 0% 处长期无进度，因此改用本机 Chrome；手动关节测试使用 `fill()` 操作 `range` 控件时报 `Malformed value`，改为设置原生 value 并派发冒泡的 input/change 事件。修正后 3/3 路径通过，五秒平均 59.0 FPS。

独立整体审查随后发现两项高优先级缺口：播放循环只在终点提交姿态，以及笛卡尔 IK 失败被零运动轨迹掩盖。新增红灯测试后，仿真状态按采样时间插值六轴、暂停可续播；IK 失败改为 `IK_FAILURE` 阻断报告。最终 128 个单元/集成测试与 3 条浏览器路径通过，浏览器测试还验证了播放中间至少一个关节确实变化。

次日从额度中断点恢复合并后复验：清理已合并且无改动的临时 worktree 后，lint 恢复通过；真实 Chrome 验收进一步捕获首帧时间戳早于 effect 起点的边界。新增 `TrajectoryPlayer` 回归测试先得到 `Playback time must be finite and non-negative` 红灯，再将同帧负偏差归零。最终结果更新为 15 个测试文件、129 个测试、lint、生产构建和 3/3 浏览器路径全部通过，五秒平均 58.3 FPS。
