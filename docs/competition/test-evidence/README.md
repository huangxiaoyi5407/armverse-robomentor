## 五秒代表性帧率

- 场景：打开三维 UR5，求解默认可达 IK 目标并播放 3 秒轨迹，继续观察至满 5 秒。
- 方法：真实 Chrome 页面通过 `requestAnimationFrame` 统计五秒窗口。
- 最终复验结果：292 帧 / 5011.7 ms，平均 **58.3 FPS**，达到至少 30 FPS 的验收目标。
- 环境：Intel64 Family 6 Model 197 Stepping 2；32 GB 内存；Intel Arc 140T GPU（系统报告 16 GB）；Chrome 156.0.8078.47。

Three.js 输出一条 `THREE.Clock` 已弃用警告，来自依赖内部，不影响功能或验收结果。

2026-10-24 合并后复验时发现，浏览器首个 `requestAnimationFrame` 时间戳可能略早于 effect 内取得的 `performance.now()`，产生极小负播放时间并被状态机拒绝。新增回归测试先稳定复现该错误，再在播放器边界把同帧负偏差归零；状态机对真正非法时间的防御保持不变。修复后 129/129 单元与集成测试、lint、生产构建和 3/3 Chrome 验收路径全部通过。

2026-10-24 在线试用反馈复验：新增目标坐标草稿校验，避免编辑中的空值被瞬间改写为 `0`；增加橙色末端工具朝向标记，使 J6 姿态旋转可见；增加轨迹进度条、百分比与播放时间，并将默认位移从 2 cm 扩大到 6 cm。三项回归测试先红后绿，最终 132/132 测试、lint、生产构建与 3/3 Chrome 验收通过。

2026-10-24 三 Agent 执行链路复验：修复演示规划姿态与初始姿态相同、批准轨迹只进入预览却未播放的问题。安全任务现在会自动播放明显不同的关节轨迹，危险任务仍由确定性安全门阻断。回归测试先红后绿，最终 134/134 测试、lint、生产构建与 4/4 Chrome 验收通过；五秒帧率复验为 59.1 FPS。

## 干净复现

- 在清理后的依赖目录执行锁文件驱动的 `npm ci`：**22 秒**，成功安装 497 个包。
- Next.js 开发服务器实测约 0.6 秒报告 Ready；即使计入克隆、复制环境文件和手动打开浏览器，明显低于 10 分钟要求。
- 首次沙箱内计时因 DNS 隔离失败，未计入结果；上述 19.1 秒来自允许联网后的成功执行（退出码 0）。

完整 `npm audit` 报告 3 个告警（1 moderate、2 critical），均位于 Vitest 的 `@vitest/mocker`/`tinypool` 开发测试依赖链；`npm audit --omit=dev` 为 0。自动修复会强制升级到存在破坏性变更的 Vitest 5，因此未执行 `npm audit fix --force`，后续在兼容升级窗口处理。
