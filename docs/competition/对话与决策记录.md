## 3. 当前项目定义

### 暂定名称

**RoboMentor UR5——多 Agent 驱动的机械臂运动学交互教学平台**

### 目标用户与痛点

- 目标用户：自动化类专业学生，重点面向学习机械臂运动学、机器人技术、运动控制或智能制造的学习者。
- 核心痛点：DH 参数、坐标变换、正逆运动学、雅可比矩阵和奇异点较抽象，静态课本难以呈现参数变化与机械臂运动的实时关系。
- 解决方式：通过 UR5 3D 仿真、实时数学参数、轨迹回放与多 Agent 解释，让学生可以操作、观察、验证和理解。

### 多 Agent 职责

1. **任务规划 Agent**：将自然语言任务拆解为可执行步骤。
2. **安全审查 Agent**：检查越界、奇异点、碰撞和轨迹风险。
3. **教学解释 Agent**：解释关节运动、公式、求解结果和失败原因。

Agent 不直接控制仿真底层。运动学、碰撞检测和状态更新由确定性程序完成，避免大模型幻觉导致不稳定。

## 8. 已确认的页面与教学设计

### 2026-10-22：设计第 2 部分已确认

- 采用单一“仿真实验台”主界面，不拆分为大量独立页面。
- 顶部：章节、实验和在线 AI / 演示模式。
- 左侧：知识点、公式解释、实验步骤和思考题。
- 中央：UR5 3D 机械臂、坐标系、目标点、障碍物与轨迹。
- 右侧：六轴角度、末端位姿、矩阵、雅可比数据和奇异点状态。
- 底部：用户指令、规划 Agent、安全 Agent、仿真执行和教学 Agent 的时间轴。

已确认七个教学章节：

1. 认识 UR5。
2. DH 参数与坐标变换。
3. 正向运动学。
4. 数值法逆向运动学。
5. 雅可比矩阵与奇异点。
6. 关节空间与笛卡尔空间轨迹规划。
7. 障碍物环境下的多 Agent 安全任务挑战。

交互原则：

- Agent 以可观察工作流呈现，不做成三个相互对话的聊天框。
- 安全 Agent 必须调用确定性检测程序，不能仅凭大模型判断。
- AI 失败或无密钥时，自动使用内置演示结果，并明确标识当前模式。
- 主要适配桌面端，移动端仅保证查看。
- 整体视觉方向为深色工业实验室，3D 机械臂始终为视觉中心。

## 10. 已确认的架构与 Agent 约束

### 2026-10-22：设计第 3 部分已确认

系统分为教学与界面层、仿真状态层、机器人确定性计算层、多 Agent 编排层和 AI 适配层。在线 AI 与内置演示模式共用同一接口。

确认的工程约束：

- 内部长度统一使用米、角度使用弧度、时间使用秒；界面层负责转换为毫米和角度。
- 运动学、雅可比、轨迹和安全算法实现为不依赖 React 或 3D 场景的纯函数。
- 正向运动学使用齐次变换矩阵连乘。
- 逆向运动学首版使用阻尼最小二乘数值法。
- 雅可比矩阵使用几何法计算，奇异性参考最小奇异值与可操作度。
- 轨迹规划首版包括关节空间三次/五次插值和笛卡尔直线插值。
- 碰撞检测首版使用连杆简化包围体与障碍物包围盒。

Agent 安全约束：

- 规划 Agent 只能输出通过 Zod 校验的受限 JSON 计划，不允许生成或执行任意 JavaScript。
- 任务动作必须来自预定义白名单。
- 确定性程序负责工作空间、逆解、关节限位、奇异点、碰撞和轨迹判定。
- 程序判定危险时必须拒绝执行，Agent 不能覆盖。
- Agent 返回非法 JSON 时最多重试一次，失败后转为规则模板。
- 无 API 密钥、超时或限流时转为内置演示模式，并在界面中明示。
- 逆运动学不收敛、目标越界或轨迹危险时不修改机械臂最终状态。

## 11. 已确认的测试与参赛证据设计

### 2026-10-22：设计第 4 部分已确认

- 建立单元、集成和端到端三层测试。
- 核心数值验收目标：逆解位置误差不超过 1 毫米，姿态误差不超过 0.5 度。
- 所有轨迹必须通过关节限制和安全检查，危险轨迹禁止执行。
- AI 失败后在 15 秒内进入演示模式。
- 无 API 密钥时七个教学章节和预置 Agent 案例仍可使用。
- 建立 `prompt-history`、`test-evidence`、`screenshots`、第三方说明和提交检查清单。
- 每份核心 Prompt 记录目标、问答、技术取舍、文件变更、测试结果、Bug 修复和 Git 提交。
