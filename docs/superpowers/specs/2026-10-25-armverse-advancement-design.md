# 臂境智教 A 组晋级版设计

## 1. 设计意图

将现有“UR5 数字孪生与多 Agent 教学演示”升级为面向高校自动化、机器人工程与智能制造专业的实验教学平台。作品以柔性制造产线综合实验为主线，把运动学、轨迹规划、控制实验、确定性安全校验、学习过程记录和 AI 教学评价组成完整闭环。

职业院校实训和企业培训保留为可扩展场景，不作为项目唯一定位。

## 2. 目标用户与价值

### 学生

- 在浏览器中完成机械臂运动学、轨迹、安全和控制实验。
- 获得与具体错误事件绑定的解释，而不是通用聊天回答。
- 一键生成包含过程证据、指标和反思问题的实验报告。

### 教师

- 使用预设班级和实验任务快速演示完整教学流程。
- 查看班级完成度、常见错误、风险事件和实验成绩分布。
- 追溯某次实验从操作到安全阻断、修正和完成的全过程。

### 评审

- 无需账号、密钥或真实设备即可体验完整流程。
- 在 5—8 分钟内看清场景价值、算法深度、Agent 边界和开发证据。

## 3. 数据边界

- 不声称使用学校、教师或真实学生提供的数据。
- 不进行或声称进行自动化专业学生试用、问卷或效果提升实验。
- 班级、学生、成绩和操作日志全部采用固定种子生成的合成教学数据。
- 页面和报告统一标注“教学演示合成数据，不代表真实学生表现”。
- 合成数据覆盖正常完成、目标不可达、碰撞风险、接近奇异位形、超速和重复无效尝试等典型案例。
- 任何 AI 生成评价必须引用系统实际记录的指标和安全事件，不能虚构学习结论。

## 4. 核心教学场景

### 柔性制造产线机械臂路径规划与安全控制综合实验

学生需要控制 UR5 完成取料区、检测区和放料区之间的搬运任务，并满足：

- 目标点可达；
- 关节不越限；
- 轨迹不穿越人员安全区和设备禁入区；
- 避免危险奇异位形；
- 速度和加速度满足教学阈值；
- 完成规定实验步骤并保留操作证据。

场景采用程序化几何和合成工件，不引入未经授权的 CAD、校徽、企业标识或真实生产数据。

## 5. 产品结构

### 5.1 学生实验台

- 保留现有七章实验、UR5 三维场景、运动学遥测和三 Agent 工作流。
- 增加综合实验任务卡、步骤进度、完成条件和评分指标。
- 记录目标修改、求解、预览、播放、阻断、重置和章节切换事件。
- 对错误事件提供“发生原因—算法依据—如何修正”的 AI 讲解。
- 完成实验后生成可打印的实验报告。

### 5.2 教师工作台

- 提供固定的“自动化 2301 班”合成示例，不需要登录和后端数据库。
- 展示任务完成率、平均尝试次数、平均安全得分、错误类型分布和需要辅导的学生列表。
- 可进入单个合成学生的实验记录，查看事件时间线和报告。
- 所有统计都能由展示的合成记录重新计算，避免只有装饰性图表。

### 5.3 实验报告

报告包括：

- 实验目标与任务；
- 初始、目标和最终关节状态；
- 关键轨迹与运动学指标；
- 安全检测结果及错误时间线；
- 学习目标完成情况；
- 教学 Agent 基于真实事件生成的解释和改进建议；
- 数据来源声明和生成时间。

首版使用浏览器打印导出 PDF，不增加云端文件服务。

### 5.4 错误溯源

采用只追加事件模型，至少记录：

- 时间、操作类型和实验步骤；
- 操作前后关节或目标值；
- IK、轨迹和安全检查结果；
- 稳定错误码；
- 是否被确定性安全门阻断；
- 对应的教学解释。

页面支持按严重程度和错误类型过滤。

## 6. Agent 角色调整

- **规划 Agent：** 将实验指令转换为白名单机械臂动作。
- **安全督导 Agent：** 解释确定性安全引擎的检测结果，但无权覆盖结果。
- **教学评价 Agent：** 读取实验指标和事件记录，生成针对性讲解与报告内容。

Agent 不直接执行代码、不访问未授权数据、不自行给出最终安全结论。确定性运动学、轨迹和安全模块仍拥有执行否决权。

## 7. 控制实验增强

### 7.1 PID 教学实验

- 单关节期望角度跟踪；
- Kp、Ki、Kd 可调；
- 展示期望值、实际值、误差、超调量、稳态误差和调节时间；
- 提供稳定的预设参数和明显欠调、过调案例；
- 教学 Agent 仅依据计算结果解释参数影响。

### 7.2 轻量动力学

- 教学级单关节或简化多关节模型；
- 可调负载、摩擦和惯性；
- 显示估算扭矩、速度和加速度；
- 明确标注“教学简化模型，不用于真实机械臂选型或安全控制”。

不在本阶段实现完整刚体动力学或宣称工业精度。

## 8. 外部连接能力

本阶段只实现低风险、可复现的接口展示：

- 导出 ROS 2 `JointTrajectory` 兼容 JSON；
- 提供 WebSocket 设备网关状态与消息格式模拟；
- 展示连接、心跳、遥测、急停和断线状态机。

不宣称已经连接真实 UR5，不要求评委安装 ROS 2，也不让网络设备指令绕过安全门。

## 9. 明确不做

- 真实学校或学生数据；
- 用户试用研究及效果提升结论；
- 摄像头视觉识别；
- 多机械臂协同；
- 强化学习训练；
- 完整工业刚体动力学；
- 未经验证的真实机械臂控制。

这些功能会分散高校实验教学主线，并增加无法在比赛材料中证明的风险。

## 10. 技术方案

- 继续使用 Next.js、React、TypeScript、React Three Fiber、Zustand、Zod、Vitest 和 Playwright。
- 教学数据、事件、评分和控制算法优先实现为纯 TypeScript 模块。
- 浏览器本地状态负责当前演示会话；固定合成数据放在版本控制中，保证离线复现。
- 报告使用可打印 React 页面，不引入新的文档后端。
- 图表优先采用轻量 SVG/Canvas 或现有能力，避免为了仪表盘引入大型依赖。
- 新功能必须保持无密钥 Demo、十分钟复现、确定性安全门和现有测试路径。

## 11. 方案比较与选择

### 产品落地优先

只做班级、报告和教师看板，完成度高，但对 A 组而言控制理论增量不足。

### 技术深度优先

集中实现动力学、PID 和 ROS 2，技术密度高，但容易退化成算法集合，教学价值闭环不完整。

### 教学产品与控制实验融合版（选定）

以班级实训、错误溯源和报告建立应用闭环，以 PID 和轻量动力学补充 A 组专业深度，同时保留多 Agent 安全创新。该方案在竞赛价值、实现风险和演示清晰度之间最均衡。

## 12. 分阶段交付

### 阶段一：教学产品闭环

1. 合成数据模型与柔性制造综合实验；
2. 实验事件记录与错误溯源；
3. 教学评价 Agent 与一键实验报告；
4. 教师工作台和可重算班级指标。

### 阶段二：A 组技术增强

1. PID 控制实验；
2. 教学级负载、摩擦和惯性模型；
3. 控制指标与 AI 解释。

### 阶段三：接口与参赛证据

1. ROS 2 轨迹 JSON 导出；
2. WebSocket 设备网关模拟；
3. 浏览器验收、性能和十分钟复现；
4. 5—8 分钟视频脚本和 30 页以内技术文档。

## 13. 验收标准

- 评委无需登录即可切换学生实验台和教师工作台。
- 至少一个综合实验可从任务开始运行到报告生成。
- 安全操作会执行，危险操作会被阻断并留下可解释事件。
- 报告中的每项数据都能追溯至当前实验记录。
- 教师看板指标能由合成记录确定性重算。
- PID 预设案例能稳定呈现欠调、合理和过调差异。
- 页面明确披露合成数据与简化动力学边界。
- 原有单元测试、浏览器验收、生产构建和在线演示继续通过。
